# Manager-shortlist analysis examples

Set `meta.data_basis` to `gradient_governed` or `mixed`. The source table columns are exactly `Tag`, `Evidence`, `Basis`, `Tool / view`, `Key parameters`, `As of`, `Data scope`, `Validation`, `Digest`. Keep factual screening evidence separate from governed performance evidence, and do not advance a candidate whose governed performance evidence is unavailable.

## Candidate evidence

**Strong example (TEST):** Observation: Three of five candidates met the mandate screen; one identity match remained advisory [S2]. Why it matters: Only resolved candidates support governed investment comparison. Uncertainty: The unresolved identity has no linked return evidence for one candidate. What would change the view: A canonical match returning at least 36 monthly observations.

## Performance comparison

**Strong example (TEST):** Observation: Candidate A led its benchmark by 0.6 points while Candidate B trailed by 0.2 [S4]. Why it matters: Separately matched evidence avoids imposing one mandate benchmark. Uncertainty: Candidate C has no governed downside-capture result. What would change the view: A governed response returning Candidate C's relative return and downside capture.

## Advance/reserve/reject rationale

**Strong example (TEST):** Observation: Candidate A exceeds the user's excess-return threshold by 60 bps and meets the 90% downside-capture ceiling; Candidate C lacks capture evidence [S2][S4]. Why it matters: Advancement applies benchmark-relative criteria, not peer rank. Uncertainty: Three-window persistence has not been returned. What would change the view: Any window below 0 bps excess, above 90% capture, or resolving Candidate C's gap.
